*Real Fans First · AI-Powered Concert Ticketing on U-topia*

> **U-Hackathon 2026 · Track 1: AI** — *"Build any app that uses AI tools to solve a real-world problem."*
> FLOW Summit 2026 · Avani Sukhumvit Bangkok · 15–16 ตุลาคม 2026

---

## 1. สรุปไอเดียใน 1 ประโยค

**แอปกดบัตรคอนเสิร์ตที่ใช้ U-topia Wallet เท่านั้น โดยให้ "สิทธิ์กดบัตรก่อน" กับคนที่ใช้ U-topia บ่อยและสม่ำเสมอ และใช้ AI คัดบอท คนปั๊มแต้ม และพ่อค้าบัตรผีออก** แฟนตัวจริงจึงได้บัตร ส่วน U-topia ได้ผู้ใช้ใหม่กับธุรกรรมจำนวนมากทุกครั้งที่มีคอนใหญ่

## 2. ปัญหาจริง (Real-World Problem)

| ฝั่ง | ปัญหา |
|---|---|
| **แฟนเพลง** | กดบัตรไม่ทัน เว็บล่ม บอทแย่งบัตรหมดในไม่กี่นาที บัตรผีขายต่อแพงหลายเท่า และโดนมิจฉาชีพหลอกขายบัตรปลอม |
| **ผู้จัดคอนเสิร์ต** | ไม่รู้ว่าใครเป็นแฟนตัวจริง เสียชื่อเพราะบัตรผี และไม่มีระบบ loyalty ที่ใช้ได้จริง |
| **U-topia** | เพิ่งเปิดตัวแอป ต้องการผู้ใช้ใหม่ และอยากให้ผู้ใช้ทำธุรกรรมบ่อยในชีวิตประจำวัน |

---

## 3. บริบทของ U-topia (ข้อมูลจาก u-topia.com)

- **Wallet (Non-custodial):** ผู้ใช้ถือคีย์เอง มี swap, send, receive และ cross-chain
- **U-Pay:** จ่ายเงินข้ามประเทศโดยไม่เสียค่า FX หรือค่าธรรมเนียมโอนต่างประเทศแพง ๆ
- **U-Card:** บัตร Visa แบบเสมือนและแบบจริง แจ้งเตือนการใช้จ่ายแบบเรียลไทม์ ตั้งวงเงินได้
- **Accounts:** ถือได้หลายสินทรัพย์ ทั้ง BTC, ETH, USDT, ทองคำ, หุ้นโทเคน และสกุลเงินต่างประเทศ
- **U-center:** ชุมชนสมาชิก มีแพ็กเกจ Bronze / Silver / Gold / Platinum / Diamond และระบบ Flow rank

➡️ U-Ticket ต่อยอดจาก **U-Card + U-Pay + Wallet + U-center tiers** ที่มีอยู่แล้ว

## 4. แนวคิดหลัก: "นับความถี่ ไม่นับยอดเงิน"

ระบบให้รางวัลกับ **การใช้งาน U-topia จริงอย่างสม่ำเสมอ** ไม่ได้ดูว่าใครจ่ายเงินมากที่สุด คนจึงอยากใช้แอปทุกวัน และคนรวยไม่ได้เปรียบ

| ✅ นับคะแนน | ❌ ไม่นับ / นับน้อย |
|---|---|
| รูด U-Card ซื้อกาแฟ 60 บาท ได้ 1 ครั้งเต็ม | ยอดเงินก้อนใหญ่ครั้งเดียว (มีเพดานต่อครั้ง) |
| ใช้ทุกวันต่อเนื่อง (streak) | โอนวนในกระเป๋าตัวเอง |
| ใช้หลายแบบ: รูดบัตร, U-Pay, swap | ทำ 50 รายการภายใน 5 นาที |
| จ่ายกับร้านค้าที่หลากหลาย | จ่ายเพื่อนคนเดิมซ้ำ ๆ |

## 5. Fan Score: สูตรคำนวณสิทธิ์

```
Fan Score = ความถี่ของธุรกรรม        (40%)
          + ความสม่ำเสมอ / Streak    (25%)
          + ความหลากหลายของการใช้งาน (20%)
          + ระดับ U-center            (15%)

          × Trust Multiplier (0.0 – 1.0)  ← AI ให้ ถ้าเจอการปั๊มแต้มจะลดลง
```

### ระดับ (Tier) และสิทธิ์

| Tier | สิทธิ์ presale | สิทธิพิเศษ |
|---|---|---|
| 💎 Diamond | เข้าก่อน 2 ชั่วโมง | ส่วนลด + สิทธิ์เลือกโซนก่อน |
| 🥇 Gold | เข้าก่อน 1 ชั่วโมง | ส่วนลด |
| 🥈 Silver | เข้าก่อน 30 นาที | แลกแต้มเป็นส่วนลดได้ |
| 🎟️ General | เปิดขายทั่วไป | — |

## 6. ลูปดึงผู้ใช้เข้า U-topia (Growth Loop)

```
① ประกาศคอนล่วงหน้า 30 วัน
   "อยากได้สิทธิ์ presale ต้องสะสม Fan Score ใน U-topia"
        ↓
② คนใหม่สมัคร U-topia และรับ U-Card          → U-topia ได้ผู้ใช้ใหม่
        ↓
③ ใช้จ่ายในชีวิตประจำวันผ่าน U-topia 30 วัน   → U-topia ได้ธุรกรรม
        ↓
④ เปิดขายเป็นรอบตาม Tier (Diamond → Gold → Silver → ทั่วไป)
        ↓
⑤ หลังคอนจบ ใช้แต้มที่เหลือแลกส่วนลด ของที่ระลึก หรือสิทธิ์สมาชิกแฟนคลับ
        ↓
⑥ เริ่มเก็บแต้มรอบใหม่สำหรับคอนถัดไป       → ผู้ใช้ไม่หายไปหลังคอนจบ 🔁
```

## 7. ฟีเจอร์ AI (ทำให้ตรงโจทย์ Track 1)

| # | ฟีเจอร์ | AI ทำอะไร |
|---|---|---|
| 1 | **AI Missions** | ดูพฤติกรรมแต่ละคนแล้วสร้างภารกิจเฉพาะตัว เช่น *"อีก 4 รายการคุณจะขึ้น Gold ก่อน presale ลองจ่ายค่ากาแฟด้วย U-Card สัปดาห์นี้"* |
| 2 | **ทำนายโอกาสได้บัตร** | *"ด้วยคะแนนตอนนี้ โอกาสได้โซน A คือ 35% ถ้าใช้ต่อเนื่องอีก 7 วันจะเพิ่มเป็น 70%"* ช่วยกระตุ้นให้ใช้ต่อ |
| 3 | **ตรวจจับการปั๊มแต้มและบอท** | จับโอนวน รายการถี่ผิดปกติ หลายบัญชีที่เชื่อมกัน และยอดที่พุ่งก่อนวันเปิดขาย แล้วลด Trust Multiplier พร้อมอธิบายเหตุผล |
| 4 | **อธิบายคะแนน** | ผู้ใช้กดถามได้ว่า "ทำไมได้ Silver?" แล้ว AI ตอบเป็นภาษาไทยที่เข้าใจง่าย |
| 5 | **AI Concierge** | แชตบอกงบกับความต้องการ เช่น *"งบ 5,000 อยากเห็นเวทีชัด"* แล้ว AI แนะนำโซนที่เหมาะ |
| 6 | **ตลาดขายต่อที่ปลอดภัย** | ขายต่อในแอปได้ไม่เกินราคาหน้าบัตร และ AI ตรวจโพสต์หรือแชตขายบัตรนอกระบบว่าเป็นสแกมหรือไม่ |

## 8. ระบบแต้มรีวอร์ด (Rewards)

- ได้แต้มจากธุรกรรมที่ผ่านการตรวจของ AI ว่าเป็นการใช้จริงเท่านั้น
- **ใช้แต้มแลก:**
  - ส่วนลดค่าบัตรคอนเสิร์ต
  - สิทธิ์ presale เพิ่มเติม
  - สิทธิ์สมาชิกแฟนคลับ (Fan Membership)
  - ของที่ระลึก หรือสิทธิ์ Meet & Greet
- แต้มมีวันหมดอายุ เพื่อกระตุ้นให้ใช้งานต่อเนื่อง

## 9. ขอบเขต MVP สำหรับ Hackathon

### หน้าจอ
1. **หน้าคอนเสิร์ต** และปุ่มเชื่อมกระเป๋า U-topia (จำลอง)
2. **Dashboard Fan Score**: คะแนน, Tier, streak, AI Missions และคำอธิบายจาก AI
3. **หน้าคิว presale**: AI ไล่เรียงลำดับผู้ใช้สด ๆ และแสดงบัญชีที่ถูกจับว่าปั๊มแต้ม
4. **แชต AI Concierge**: แนะนำโซนตามงบ
5. **หน้าแลกแต้ม**: ส่วนลดและสิทธิ์สมาชิก

### ข้อมูลจำลอง (Mock Data)
- ผู้ใช้ 20–30 คน แบ่งเป็นแฟนตัวจริง, คนใช้งานปกติ, **บัญชีปั๊มแต้ม** และ **บอท**
- ประวัติธุรกรรม U-topia ย้อนหลัง 30 วัน (U-Card, U-Pay, swap)
- เหตุผล: U-topia ยังไม่มี API สาธารณะ

### Tech Stack
| ส่วน | เทคโนโลยี |
|---|---|
| Frontend | Next.js + Tailwind CSS |
| AI | Claude API (วิเคราะห์ธุรกรรม, สร้างภารกิจ, อธิบายคะแนน, Concierge) |
| Backend / DB | Next.js API Routes + JSON / Supabase |
| Deploy | Vercel |

## 10. สคริปต์เดโมบนเวที (3 นาที)

1. **ปัญหา (30 วิ):** "ทุกครั้งที่บัตรคอนเปิดขาย บอทและบัตรผีชนะแฟนตัวจริง"
2. **ผู้ใช้ปกติ (45 วิ):** เปิด Dashboard ให้เห็น Fan Score, AI Missions และโอกาสได้บัตร
3. **ดวลกัน (60 วิ):** แฟนตัวจริงกับบัญชีปั๊มแต้มเข้าคิว presale พร้อมกัน แล้ว AI จับบัญชีปั๊มแต้มได้ อธิบายเหตุผล และเลื่อนแฟนตัวจริงขึ้นไปก่อน
4. **AI Concierge (30 วิ):** พิมพ์งบ แล้วได้คำแนะนำโซน
5. **คุณค่าทางธุรกิจ (15 วิ):** ตัวเลขผู้ใช้ใหม่และธุรกรรม (หัวข้อ 11)

## 11. คุณค่าทางธุรกิจ (ตัวเลขสมมติเพื่อประกอบการพิช)

> คอนใหญ่ 1 งานมีคนแย่งบัตร **200,000 คน**
> ถ้า 10% สมัคร U-topia เพื่อเก็บคะแนน 30 วัน และทำเฉลี่ยวันละ 2 รายการ
> = **ผู้ใช้ใหม่ 20,000 คน** และ **1.2 ล้านธุรกรรม** ต่อคอน 1 งาน

*(ตัวเลขนี้เป็นค่าประมาณ ต้องบอกบนเวทีว่าเป็นสมมติฐาน)*

### ใครได้อะไร
| ฝ่าย | ได้อะไร |
|---|---|
| **แฟนเพลง** | โอกาสได้บัตรที่ยุติธรรม ไม่แพ้บอท และใช้แต้มแลกส่วนลดได้ |
| **ผู้จัดคอน** | รู้ว่าใครเป็นแฟนตัวจริง ลดบัตรผี และได้ข้อมูลกลุ่มแฟน |
| **U-topia** | ผู้ใช้ใหม่ ธุรกรรมต่อเนื่อง และผู้ใช้อยู่ต่อหลังคอนจบ |

## 12. ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| ถูกมองว่าคนรวยได้เปรียบ | นับความถี่ ไม่นับยอดเงิน และตั้งเพดานต่อรายการ |
| คนปั๊มแต้มหรือโอนวน | AI ตรวจจับและลด Trust Multiplier |
| ข้อกฎหมาย: ธปท. ไม่อนุญาตให้ใช้คริปโตจ่ายค่าสินค้าโดยตรงในไทย | จ่ายค่าบัตรผ่าน **U-Card (Visa)** ซึ่งตัดเป็นเงินบาท ไม่ได้จ่ายเป็นคริปโต |
| คนที่ไม่ใช้ U-topia ซื้อบัตรไม่ได้ | ยังมีรอบขายทั่วไป (General) ให้ทุกคน U-Ticket ใช้กับรอบ presale เป็นหลัก |
| ข้อมูลส่วนบุคคล (PDPA) | ใช้ข้อมูลธุรกรรมเมื่อผู้ใช้ยินยอมเท่านั้น และให้ AI ดูเฉพาะข้อมูลสรุป |
